# 姓名标记和“某某，欢迎光临”

## 预期行为

明确登记“张三”后，系统检测其清楚人脸，连续三次与姓名库一致且跨越至少0.5秒，才显示“人脸：张三”，并排队播放“张三，欢迎光临”。未登记、匹配分数不足或多人身份歧义均不播报姓名。

人体编号与姓名分开：人体01可能是当前唯一人物；姓名ID是明确登记的128维SFace特征对应人员。槽位重新出现、人体不连续或漏检时撤销姓名绑定。重新看清人脸后才能重新确认。

## 登记

1. 关闭现有相机/视觉窗口。
2. 控制中心点“登记人脸姓名”，输入要显示与播报的姓名。
3. 只让该人员一张人脸入镜，正常正面照明，先正脸再小幅转头。
4. 程序检查脸尺寸、亮度、清晰度与样本一致性，采8次才写入，60秒未完成则不写入。
5. 退出/取消不写入。成功后重新启动预览，运行中的视觉不会热加载登记库。

```bash
bash run.sh --mode enroll --name '张三'
bash run.sh --mode list
# 删除指定人脸ID；不要在视觉运行时修改姓名库。
app/.venv/bin/python app/tools/enroll_named_face.py --delete 1
```

再次用相同姓名登记会向同一身份追加样本，最多保留30个。如果两个人同名，应使用可区分的显示名，例如“张三A”“张三B”，否则会合并为一个身份。姓名允许1～24个字符，不允许控制字符或路径分隔符。姓名不用于拼接shell命令或音频路径。

姓名库为 `app/data/named_faces.json`，含姓名和人脸特征，**不含登记照片**。特征同样是个人敏感数据，应征得当事人同意并保管；默认Git忽略，上传包不包含。

## 匹配与人体绑定

- YuNet检测置信度0.85、NMS 0.3；SFace对齐112×112人脸并提取128维归一化向量。
- 特征余弦分数至少0.45，且领先次高身份至少0.05，才给出候选姓名。该阈值是工程初始配置，不代表确定准确率。
- 人脸须唯一落在一个人体框上方55%区域，至少80%脸框面积位于该区域；多人体重叠、多脸落在同一身体、同ID被多脸认领，拒绝确认。
- 异步结果保留原拍摄时间和人体连续性令牌；超过0.9秒的结果丢弃，绑定有效期1.5秒。它不能作为新的舵机坐标。
- UI人脸框按当前连续人体框映射，属于姓名展示的近似位置；精确控制始终使用新鲜人体检测。

## 防止反复欢迎

默认同一姓名连续在场只播报一次。至少离开已验证姓名状态8秒且距离上次欢迎至少60秒，才允许再欢迎；短暂转头、少量漏检和短暂离开不会反复播报。因为系统看到的是“已确认人脸是否出现”，长时间背对镜头也可能被算作离场，不能等同物理离开。

语音队列最多3条，独立线程执行本机 `espeak-ng -v cmn -s 155 --stdin`，超时12秒，不使用shell或网络。缺语音工具/声卡、命令失败不会退出人体跟随；UI显示语音错误。外部音频命令被调用不等于扬声器一定出声，须现场听音验收。

## 两种跟随方式

**默认标签模式**：按已有单人自动/手动人体锁定规则跟随；人脸只加姓名和欢迎。陌生人也可能被人体规则选中。适合展示“人体跟随＋认识的人欢迎”。

**指定姓名身份模式**：

```bash
bash run.sh --mode full --follow-face 1
```

只给对应已登记人脸ID的、仍有效且唯一的人体框发有效控制。身份过期、转身无法确认、未知或歧义时，发送无效控制，保留原主控停车/回中逻辑。不把旧人脸框或预测框当作新坐标。

本实现没有活体检测、防照片攻击或年龄/性别推断。照片/屏幕也可能被识别成人脸，不能用于门禁授权、收费或其他身份安全决策。
