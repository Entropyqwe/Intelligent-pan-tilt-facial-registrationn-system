# 软件测试与实物验收

本次验收分为“已在Windows离线执行”和“仍须在板端完成”，不能将单元测试通过当作电机或音频实测通过。

## 已执行的软件检查

具体次数、结果与范围见同目录 `TEST_RESULTS.md`。包含既有跟踪、协议、超时、方向/限位、曝光保护测试，以及新增姓名库、人脸时序绑定、多人歧义、语音去重/失败隔离与统一入口测试。

真实ONNX测试只用合成图：YuNet空图检测、SFace实际特征提取、特征维数与姓名库回读。合成数据验证接口可用，**不验证真人识别准确率或欢迎现场效果**。

原STM32副本HEX的SHA256必须与交接文档相同。Keil引用文件均应存在；本次未变更STM32，无需为人脸/语音功能重新烧录现有同版本主控。

复跑：

```bash
app/.venv/bin/python tools/models.py --verify
cd app
.venv/bin/python -m unittest discover -s tests -v
cd ..
app/.venv/bin/python tools/audit_package.py
app/.venv/bin/python tools/verify_files.py
# 需系统已有gcc，编译输出只在临时目录，不烧录。
app/.venv/bin/python tools/test_firmware.py
```

若刚下载仓库但未恢复模型，真实模型用例会失败，先运行模型恢复工具。这是明确的依赖检查，不要删测试掩盖缺文件。

## 实物验收步骤

| 顺序 | 操作 | 合格标准 | 执行者 |
|---|---|---|---|
| 1 | 断开VM，核对供电/共地/三路信号/超声波 | 接线、逻辑电平与机械行程正确 | 用户/电控 |
| 2 | 仅相机预览，人物头到腰入镜 | 彩色、亮度正常、旋转正确；记录真实采集FPS | 用户 |
| 3 | 中文语音测试 | 扬声器实际说出欢迎词，音量与设备正确 | 用户 |
| 4 | 明确登记一人，再人脸预览 | 姓名正确；三次确认后欢迎；未知者不报姓名 | 用户 |
| 5 | 连续在场、短暂转头/遮挡、离开再回来 | 持续在场不重复欢迎；短暂遮挡不频繁播报 | 用户 |
| 6 | 两人同框/交叉、相似衣服、照片/屏幕 | 歧义不报确定姓名；记录误认；照片攻击无防护须清楚知晓 | 用户 |
| 7 | 单轴pan/tilt/front验证 | 两侧停留/回中，无卡顿嗡响，仍处原范围 | 用户/电控 |
| 8 | 独立距离监听，在30/35/50/100cm等已知位置测试 | D1有效且误差记录；拔ECHO/遮挡无效，UI正确显示 | 用户/电控 |
| 9 | 完整视觉，VM仍断开 | 人体有效→G1/S1→A1/G2→三路动作，D1/M1刷新 | 双方 |
| 10 | 指定身份模式，遮挡/转身/换人 | 身份过期或歧义后有效转向撤销，不追未知身份 | 双方 |
| 11 | 同场60秒基础版与人脸版测速 | 记录FPS、p95帧龄、人脸耗时、有效跟踪率，公开实际数据 | 算法方 |
| 12 | 完成标定后，先架空电机，再低速场地 | 缓升、距离停车、传感器/串口/视觉故障停车均实际通过 | 用户/电控 |

本次新副本没有接管设备或开展以上实物测试；旧工程历史测试不能自动变成新增功能的验收。用户必须参与机械观察、实际距离摆放、人员入镜、音箱听音以及电源/VM操作。

## 需要记录的数据

建议每次记录系统镜像、SoC/SDK、摄像头型号/模式、照明、人物距离/脸大小、模型SHA、软件版本、三路范围、实际FPS、p95年龄、漏检/误认/重复欢迎次数。不要用空画面或相机峰值FPS代替有人跟踪的处理FPS。

如需上传测试报告，先去掉个人姓名、人脸图片、私人IP和串口路径；真人录像与姓名特征库不要放公共仓库。
